# ADR-0005：面板自带深浅两套配色，默认深色

- 状态：已采纳（2026-11-20）
- 相关：[2026-11-20_v6-polish.md](../specs/2026-11-20_v6-polish.md) §3.6、§4.1；取代 [2026-11-19_v6-redesign.md](../specs/2026-11-19_v6-redesign.md) 里「系统色只用 `--dsw-alias-*`」这一条

## 背景

v6 的底色、文字色、描边、主按钮、遮罩都读宿主的 `--dsw-alias-*`，所以面板的深浅色完全跟着 DSH。Neo 在真机里提出：想默认深色，而且面板里要有切换的地方。

宿主的变量只有「当前主题」这一套值。DSH 是浅色时，面板要显示成深色，就拿不到宿主的深色值。

另外，宿主浅色主题里 `bg-base`、`bg-layer-1/2/3` 是同一个白，卡片和底分不出层次，v6 里好几处淡底色因此看不见，只能改用悬停叠色凑合。

## 决定

面板在 `.zp-root` 上定义自己的两套颜色，全部用 `--zp-*` 命名，值登记在 `docs/ui-contract/tokens.md`：

- 根节点带 `data-theme="dark" | "light"`。浅色值写在 `.zp-root`，深色值写在 `.zp-root[data-theme="dark"]`。
- 偏好 `ziwei-pro.theme`：`dark`（默认）、`light`、`auto`。`auto` 时由脚本读 `body[data-ds-dark-theme]` 解析成前两者之一，并监听它的变化。
- 样式表里不再出现 `--dsw-alias-*`，也不再用 `body[data-ds-dark-theme]` 选择器。宿主变量只保留字体族（`--dsh-font-family-text-default`）、窗口避让（`--dsh-frame-*`）和焦点框颜色（`--dsw-focus-ring-color`）。
- 深色是带一点靛色的夜空底，和首页 3D 场景的夜空接得上；浅色是浅灰底加白卡片。

## 后果

- 面板的颜色不会随宿主以后的调色自动变化。`auto` 模式下面板和 DSH 的深浅一致，但色值不保证逐一相同。
- 体检脚本的规则跟着改：字面色只许出现在登记过的 `--zp-*` 定义和阴影里（规则本身没变，登记的变量多了一组）；对比度按面板自己的底色算。
- 导出的报告文件不受影响：它一直自带配色，屏幕上跟随查看者的系统深浅色，打印一律浅色。

## 没选的做法

- **在根节点上覆盖 `--dsw-alias-*` 的值**：改动最小，但变量名说的是「宿主的值」，实际却不是，后面的人会被误导。
- **只在不一致时覆盖、一致时读宿主**：要维护两条路径，颜色还会因为走哪条路径而略有不同。
