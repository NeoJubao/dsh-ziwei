# 0004：首页 3D 场景用 Three.js r128，单文件入库，不加 npm 依赖

- 状态：已采纳（分支 `feature/v6-redesign`，未发布）
- 日期：2026-11-19
- 决策人：Neo（三个方案里选了"把 Three.js 放进仓库"）
- 相关：`docs/specs/2026-11-19_v6-redesign.md` §4.2、§4.5；`THIRD_PARTY_NOTICES.md` §5

## 背景

v6 的首页是一座可以拖动、缩放的 3D 浑天仪：金属环要有环境反射，还有星球、尘埃盘、星云和一套 HDR 后期（多级泛光、体积光、色调映射）。原型用 Three.js r128 做场景管理、PBR 金属材质和预滤波环境贴图，其余效果是自己写的着色器。

本仓库一直是单包、零运行期依赖、没有 `npm install` 这一步，`CLAUDE.md` 禁区里写着"不引入运行期依赖"。

## 决定

- 把 Three.js r128 的 UMD 压缩版（`three.min.js`，603,445 字节，MIT）放进 `vendor/three-r128.min.js`，由 `build.mjs` 拼进 `client.js`。
- `package.json` 不加任何依赖，仍然没有 `npm install`。
- Three.js 和场景代码包在 `__ziweiBootstrapSky()` 里：加载 `client.js` 时只定义这个函数，首页第一次可见时才执行；包装里用局部的 `module` / `exports` 接住 UMD 的导出，不产生 `window.THREE`。
  Three.js r128 自己会在执行时写一个版本标记 `window.__THREE__ = "128"`，这发生在首页第一次可见之后，不在加载期。
- 文件的 SHA-384 固定为 `CI3ELBVUz9XQO+97x6nwMDPosPR5XvsxW2ua7N1Xeygeh1IxtgqtCkGfQY9WWdHu`（和 cdnjs 公布的 SRI 一致），自检核对；不手改这个文件。
- 许可全文登记在 `THIRD_PARTY_NOTICES.md`，登记的提交排在入库的提交之前。
- `CLAUDE.md` 禁区的说法相应改成"不加 npm 运行期依赖；第三方代码或数据入库前，先补 `THIRD_PARTY_NOTICES.md`"。

选 r128 而不是更新的版本：r128 是原型验证过的版本；它有带全部功能的 UMD 单文件，不用打包器就能拼进现有的构建；更新的版本改了颜色管理、灯光强度和多重采样渲染目标的接口，要重调一遍画面。

## 为什么没选别的

| 方案 | 没选的原因 |
|---|---|
| 手写 WebGL2，不用第三方库 | 要重写约 2000 行渲染代码（矩阵、网格、帧缓冲、PBR 和环境贴图预滤波），效果大概率不如原型，出问题也更难查 |
| 首页不上 3D，用静态星图 | 没有原型里可以拖动的首页；Neo 明确要"震撼的视觉表现"和"鼠标自由交互" |
| 加 `three` 作为 npm 依赖 | 要引入 `npm install` 和打包器，改变整个仓库的构建方式 |
| 用宿主的懒加载分片（`require.async`） | 协议只在 tsdown 的产物里用过，本仓库是手工拼接；先保持一个文件，以后再评估 |

## 后果

- 好处：效果和原型一致；构建方式不变；没有网络请求，离线可用。
- 代价：`client.js` 从约 360KB 变成约 960KB（多出来的是不执行的函数体，解析开销实测约 7 毫秒）；仓库里多了一个 600KB 的第三方文件；r128 是 2021 年的版本，不会再有上游修复。
- 连带的约定变化：界面约定原来禁止无限循环动画和 300ms 以上的过渡，v6 给首页星图区域开了正式豁免（spec §4.6「动效」）。
- 什么情况下要重新考虑：宿主把 `three` 放进共享模块表；或者真实 DSH 里包体积、加载时间成为问题；或者 r128 在新版 Chromium 上出现兼容问题。
