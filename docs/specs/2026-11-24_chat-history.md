# 按命盘的历史对话

- 状态：已确认（Neo，2026-11-24，在 Plan mode 里确认了 Intent）
- Issue：无

## 1. Intent

- **要做什么**：
  1. 每张盘可以存多条对话。紫微师头部的「新对话」把当前这条对话存进历史，再开一条空的；不再删除。
  2. 头部多一个「历史对话」，点开是这张盘的对话列表，可以切回任意一条接着聊，也可以单条删除（可撤销）。
  3. 对话和报告能留的盘数从 8 张提到 20 张。
- **为什么**：2026-11-24 真机反馈，原话：「紫微师里面我选了添加新对话，直接就删除了以前的对话，这个不合理。应该以命盘储存聊天会话记录吧，可以选历史对话那些？」现在的「新对话」是清空，撤销提示 6 秒后消失，之后就找不回来了。
- **约束**：
  - 禁区不变：不手改构建产物，不改 `package.json` 的 `name` / `private`，不碰 `~/.dsh/profiles/*`，不重启 DSH，不发布，不加 npm 依赖，只用黄金用例。
  - `ziwei-pro.readings.v2` 的记录格式不改：它仍然放当前对话和报告。1.6.0、2.0.0 写的记录原样可读；退回 2.0.0 只是看不到历史。
  - 历史只新增一个键 `ziwei-pro.chats.v1`，只存在本机，不上传。
  - 只改 Client 半；Host 半不动。
  - 一张盘同一时间只有一个生成任务的规则不变：任务在跑时不能开新对话、不能切对话。
- **不做什么**：历史对话的搜索、改名、导出、跨盘查看；报告不进历史（报告一张盘只有一份，照旧）；不 push、不发布。
- **成功指标**：
  - `node build.mjs && node verify/all.mjs` 全绿，`node verify/pack.mjs` 通过，`node scripts/audit-ui.mjs` 无失败。
  - 聊几句 → 新对话 → 再聊几句 → 历史对话里两条都在，点旧的那条能接着聊。
  - 关掉再打开面板、换盘再回来，历史都还在。

## 2. 用户故事

1. 作为聊完事业想换个话题的人，我点「新对话」开一条新的，刚才那条还留着。
2. 作为想回头看上次怎么说的人，我点「历史对话」，看到这张盘聊过的每一条（第一句问的是什么、哪天、几条消息），点一条就回到那条对话里。
3. 作为觉得某条对话没用的人，我在列表里删掉它；手滑了可以撤销。
4. 作为有好几张盘的人，每张盘的历史各管各的，换盘不会串。

## 3. 验收标准

### 3.1 存储

- 当保存一张盘的历史对话时，系统应把它写进 `ziwei-pro.chats.v1`：`{ [命盘 key]: [{ id, thread, updatedAt }] }`，新的在前。
- 每条对话的消息沿用现有的清理规则（最多 24 条，每条最多 60000 字，空的回答去掉）；清理后没有消息的对话不存。
- 每张盘最多留 20 条，多出来的去掉最旧的。
- 如果写不进去（配额满），系统应去掉所有盘里最旧的一条历史对话再试，直到写进去或没有可去掉的；不外抛。
- 如果存的值读不出来（不是 JSON、形状不对），系统应当成没有历史，不外抛。
- 当清除本机记录时，系统应连 `ziwei-pro.chats.v1` 一起清掉。
- `ziwei-pro.readings.v2` 的记录字段应保持 `thread, report, studioTab, name, updatedAt` 不变。
- 对话和报告最多留 20 张盘（以前是 8 张），超出时去掉最久没更新的。

### 3.2 store

- `newChat()`：当前对话有消息时，应把它存到历史最前面、清空当前对话、清掉错误和引用，返回 true，并提示已存入历史。当前对话为空、没有打开的盘、任务在跑时返回 false，什么都不变。
- `openChat(id)`：应把那条历史取出来作为当前对话；原来的当前对话有消息的话先存进历史最前面。找不到这个 id、任务在跑时返回 false。
- `removeChat(id)`：应从历史里删掉这一条并给出可撤销的提示；撤销后它回到原来的位置。已经换了盘就不撤销。
- `clearThread()`（清空当前对话，可撤销）保留，行为不变。
- 历史随这张盘的解读数据一起读进来；这张盘没有当前对话和报告、只有历史时也要读得到。
- 换盘、关面板时，历史列表应收起（回到对话）。
- `clearLocalRecords()` 之后各盘的历史都是空的。

### 3.3 界面

- 紫微师头部：有历史或当前对话有消息时出现「历史对话」按钮（有名字）；当前对话有消息时出现「新对话」。两者都没有时头部和现在一样。
- 点「新对话」：当前对话进历史，面板回到空态，出现「已存到历史对话」的提示（不是「已清空」）。
- 点「历史对话」：面板里头部和免责声明留着，中间换成列表；再点一次或点「返回对话」回到对话。
- 列表：当前对话（有消息时）排第一并标「当前」；后面是历史，新的在前。每行有标题、日期、消息条数。
  - 标题是这条对话的第一句提问；带引用的提问只取问的那句；以速览开头的写「速览解读」。
- 点一条历史：切到那条对话、回到对话视图、焦点到输入框。
- 每行有一个删除按钮（有名字）。删历史对话调 `removeChat`，删当前对话调 `clearThread`，都可撤销。
- 任务在跑时：历史行和「新对话」不能点。
- 没有任何对话时列表里是一句说明。
- 流式增量到来时列表不重画。
- 列表里每个按钮都有文字或 `aria-label`。

## 4. 设计决定

### 4.1 和前面的 spec 不一样的地方

- v6 spec 第 95 行「"新对话"清空对话，可撤销」改成：「新对话」把当前对话存进历史，再开一条空的。清空（可撤销）还在，改由历史列表里当前对话那一行的删除来做。
- v5 起的「解读记录最多 8 张盘」改成 20 张。

### 4.2 模块和接口

- `src/ui/21-storage.js`：`api.chats.load(key)` / `api.chats.save(key, list)`；`clearLocalRecords` 多清一个键；`READINGS_MAX` 改成 20。
- `src/ui/26-store.js`：reading 多一个 `chats`；`newChat` / `openChat` / `removeChat`；`session.asHistory`。
- `src/ui/80-assistant.js`：`AssistantHead` 多一个按钮；新组件 `AssistantHistory`；纯函数 `asChatTitle`。
- `src/ui/50-parts.js`：`history` 图标。
- `src/ui/css/80-assistant.css`、`i18n/80-assistant.json`、`i18n/26-store.json`。
- `docs/ui-contract/layout.md`：ASSISTANT 一行。

### 4.3 数据

- 新键 `ziwei-pro.chats.v1`：`{ [命盘 key]: [{ id: 'c-<毫秒>', thread: [{ role, content }], updatedAt: <毫秒> }] }`。
- `id` 在一张盘里不重复（同一毫秒往后挪）。
- 标题、条数不存，显示时从 `thread` 算。

### 4.4 关键决定

- 当前对话留在 `readings.v2`，历史另放一个键：旧版本读写 `readings.v2` 的方式完全不受影响，升级和降级都不用迁移。
- 切回一条历史是「取出来」而不是「复制」：同一条对话只在一个地方，不会出现两份各自往下聊。
- 历史不设全局条数上限，靠每张盘 20 条和配额满时去掉最旧的来兜底。

- 参照 `verify/ui-v6-storage.mjs`（上限、配额、读不出来）、`ui-v6-store.mjs`（清空和撤销）、`ui-v6-assistant.mjs`（头部按钮、流式的代价）里已有的同类自检。

## 6. 不在范围内

- 搜索、改名、导出、跨盘查看、置顶。
- 把历史对话交给 DSH 新会话（「在新会话里继续」仍然只带当前对话）。
- 报告的历史版本。
