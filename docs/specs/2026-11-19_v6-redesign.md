## 1. Intent

- **要做什么**：按原型重做 Client 半的界面：3D 星图首页、对话式新建命盘、一屏命盘页（本命 / 大限 / 流年 / 流月 / 流日）、右侧紫微师面板、完整报告页和新版导出文件。
- **为什么**：v5 是在旧结构上一层层加出来的，入口多、层级乱、视觉不统一。三批打磨之后整体交互仍然不满意，重做一次比继续修补便宜。
- **约束**：
  - 不改 `index.js`、`src/engine-core.js`、`src/ziwei-core.js`，不改 Host 路由和提示词。
  - 不改已有的 localStorage 键和记录结构，只新增可选键。v5 存下的命盘、对话、报告在 v6 里都能打开。
  - 不加 npm 依赖。Three.js r128 作为第三方代码入库，先登记 `THIRD_PARTY_NOTICES.md`（ADR-0004）。
  - 遵守宿主约定：顶栏第一个控件是"返回会话"、不用 `position: fixed`、避让 macOS 窗口标题带、系统色只用 `--dsw-alias-*`。
  - 加载 `client.js` 时只注册 factory。引擎在 factory 第一次物化时执行；Three.js 和 3D 场景在首页第一次可见时才执行。
- **不做什么**：
  - 不发布、不 push、不重启 DSH。
  - 不做 Host 侧的流月 / 流日提示词扩展（面板这边把定位文字拼进请求）。
  - 不补 `package.json` `files` 里缺界面源码的旧问题（包里带的是构建好的 `client.js`）。
- **成功指标**：
  - `node build.mjs && node verify/all.mjs` 全绿。
  - 界面约定体检（`scripts/audit-ui.mjs`）的历史欠账只降不升，目标清零。重做前锁着 191 处：字面色 13、字号 21、间距 91、字重 16、旧品牌色 50。
  - 预览壳里浅色 / 深色 × 窄 / 中 / 宽都对得上原型。
  - Neo 在真实 DSH 里走一遍主流程没有阻断问题。

## 2. 用户故事

1. 作为第一次打开的人，我想被一句一句地问出生辰，然后直接看到自己的盘和一段速览，不用先学会填表。
2. 作为有几张盘的人，我想一打开就看到它们，点一下进到今天的流日。
3. 作为看盘的人，我想在一屏里同时看到盘面、当前时间层级的要点、格局和我点的那一宫，不用滚动。
4. 作为看盘的人，我想切到流月、流日，并且能翻到上个月、明天。
5. 作为想深入的人，我想随时问紫微师，问题自动带上我正在看的那一层时间和那一宫。
6. 作为要一份完整解读的人，我想在它写报告的时候边写边读；写的过程中去做别的事也不丢；写完能下载成一个好看的文件。
7. 作为 v5 的老用户，我升级后原来的盘、对话、报告都还在。

## 3. 验收标准

### 3.1 首页

- 当命盘库里有盘时，首页应显示最近打开的至多 8 张盘的标签（称呼 + 公历生日 `YYYY.MM.DD`）。状态句是当前聚焦那张盘的今日流日摘要：流日命宫落在本命哪一宫、流日化禄和化忌的星、这一宫管什么。
- 当鼠标悬停或键盘聚焦某个标签时，状态句应换成那张盘的，标签多出第三行："太阳、太阴坐命 · 木三局"；命宫没有主星时是"命宫空宫，借 X"。
- 当点击标签或 3D 里的星球时，应进入那张盘的流日。
- 当在输入框里输入问题并发送时，应打开当前聚焦的盘（本命），并把问题发给紫微师。
- 快捷项有三个："看今天"（进入流日）、"这十年要注意什么"（进入大限并提问）、"排一张新盘"（进入引导问答）。
- 当点击标签上的"⋯"时，应出现改名、改生辰、删除。删除要二次确认，删除后的提示可以撤销。
- 当命盘库超过 8 张盘时，其余的盘应能在顶栏右侧的"全部命盘"列表里找到并打开。
- 如果没有 WebGL、WebGL 上下文丢失、或设置里关掉了"首页 3D 星图"，应显示静态星图（当前聚焦那张盘的浑天仪徽记）和命盘列表，以上功能照常可用。
- 如果系统开了"减少动态效果"，3D 只画静止的一帧，开场、飞入、飞出、新星诞生都直接切换。
- 开场动画在一次 DSH 运行里只播一次。

### 3.2 新建命盘

- 当命盘库里没有盘时，首页应直接进入引导问答：称呼 → 生日 → 出生时间 → 性别 → 出生城市 → 确认。这时提供"看示例盘"。
- 生日应接受 `1990年6月15日`、`1990-6-15`、`1990.6.15`、`90年6月15日`、`农历1990年五月廿三`、`农历1990年闰五月初一`；年份限 1900–2100；闰月不存在、日期不存在时说明原因。读不懂时给出带例子的提示，不清空已输入的内容。
- 出生时间应接受 `15:30`、`下午三点半`、`3点半`、`申时`、`晚子时`，并提供十二时辰快捷项（带起止钟点）。选"不确定"时提示"时辰决定命宫，请选一个最可能的时辰"，不替用户选默认时辰。
- 性别点选"男""女"。
- 出生城市复用 `ZWUi.parseBirthplace`（城市名、省 + 市、经度数字、`东经105.97°`），可以跳过；查不到时说明可以换个写法、直接填经度或跳过。
- 确认那一步显示将要排的生辰。如果真太阳时校正让时辰变了，要明说，例如："按东经 105.97° 校正后是 08:37，落在辰时（钟表时间 09:30 是巳时）"。
- 点"排盘"后：新盘自动存进命盘库；新星球从紫微星飞出；随后进入这张盘的本命，紫微师面板打开并显示这张盘的速览（见 3.4）。不自动发起任何模型请求。
- 已回答的每一项都能点回去改。
- "直接填表"打开完整的生辰表单：称呼、公历 / 农历、年月日、闰月、时、分、性别、出生城市、职业或想问的方向，以及"更多选项"里的四项排盘口径（年柱分界、月柱分界、晚子时、闰月出生）。"改生辰"用同一张表单，预填这张盘的生辰。
- 如果生辰排不出来，应留在当前步骤并说明原因。

### 3.3 命盘页

- 命盘页在窄、中、宽三档下都应一屏放完：面板本身不出现纵向滚动条。空间不够时先收说明文字（星曜解释、格局说明的行数），卡片本身不滚动。
- 顶栏有六个页签：本命 / 大限 / 流年 / 流月 / 流日，分隔线之后是"报告"。
- 左上角的时间卡跟着页签变：标题是页签名；内容是这一层的时间（例如"11月19日 · 农历十月十一 · 丁酉日"）、一句要点（这一层的命宫落在本命哪一宫、重心在哪）、四化四格。本命下的时间卡显示命宫主星、身宫和生年四化。
- 在大限、流年、流月、流日下，时间卡能前后翻一格（十年 / 一年 / 一个流月 / 一天），翻走后出现"回到今天"。翻到出生以前或超出命盘范围时提示并停住。
- 运限的分界一律按农历，和 iztro 的默认口径一致：流年从正月初一换，流月按农历月。排盘口径里的"年柱分界""月柱分界"只影响四柱，不影响运限。同一个流月里，流月命宫、干支、四化从头到尾不变。
- 闰月按"前半月归上月、后半月归下月"：闰六月十五及以前算六月，十六起算七月。时间卡要把这一点写出来（例如"农历闰六月下半 · 按七月 · 甲申月"），前后翻按流月走，不按日历上的农历月走。
- 起运之前的年份属于"童限"：时间卡写"童限（N 岁）"，不显示一个不存在的大限区间。
- 点一个宫位时：只更新十二个宫格的选中和三方四正高亮、连线、宫位卡；宫格节点不重建，入场动画不重放，时间卡和格局卡不变。
- 切页签、前后翻时：宫格节点不重建，只换宫格里的字（运限宫名、运限四化）和时间卡、中宫。
- 宫位卡显示宫名、干支、运限宫名（运限层级下）、主星（含亮度、生年四化、运限四化）、一句星曜解释、辅星、三方四正、这一宫的大限岁数；打开杂曜开关后多一行杂曜。点主星或辅星的名字，解释换成那颗星的。点三方四正里的宫名，选中那一宫。
- 格局卡列出引擎检出的全部格局（名称 + 吉 / 中 / 凶），点哪个显示哪个的说明；没有格局时写"这张盘没有明显的格局"。
- 盘面中宫显示称呼、公历和农历生日、时辰、出生地、四柱、五行局、阴阳男女、命主、身主、起运岁数、真太阳时（没校正时写"未校正"）；运限层级下多一项当前层的干支。时辰边界告警（`boundaryWarning`）在这里提示。
- 盘面有焦点时，方向键切换选中宫：左右沿十二宫的环走一格，上下跳到对宫。
- 窄档下：盘面在上，下面一张卡，用三个页签在时间卡 / 格局卡 / 宫位卡之间切换；点宫位自动切到宫位卡。
- 顶栏"更多"菜单有：复制命盘文字、显示杂曜（开关）、改生辰。
- 进入命盘的入场动画只在进入时播一次。

### 3.4 紫微师面板

- 宽档下面板和命盘并排，盘面收窄但仍一屏放完。中、窄档下面板浮在命盘上，有遮罩，Esc 和点遮罩都能关闭。
- 面板空着时显示这张盘的速览。速览是本地算出来的，不调用模型：命宫主星和一句解释、最多两个格局、当前大限、今天流日。下面是"读这张盘""写完整报告"和三个示例问题。打开面板不自动发起请求。
- "读这张盘"发的是空问题（和 v5 的速览解读一样，Host 按"速览"的格式回答），对话里不出现一句用户提问。
- 时间卡上的"解读今天 / 这个月 / 今年 / 这十年"把对应层级的定位一起发给模型：大限用 `meta.decadalFocus`，流年用 `meta.yearlyFocus`（Host 已支持）；流月、流日把定位文字拼进 `chartText` 末尾，并在 `question` 前面加一句聚焦说明。对话气泡里只显示用户看到的那句话。
- 只有从时间卡发起的提问带层级定位。在输入框里自己打的问题不带，哪怕当时停在大限或流年页签；完整报告也不带。（v5 只要停在大限或流年页签，每个请求都带，连报告也带，会把无关的问题和整份报告都拉向那一段时间。）接着写、重试沿用上一问的定位。
- "问这一宫"带上这一宫的星曜作为引用，直接提问。
- 生成中能停止。被截断或断连时保留已写的部分并给"接着写"；失败时给"重试"（用同一个问题重问，不重复出现在对话里）。
- "新对话"清空对话，可撤销。"在新会话里继续"的行为和 v5 一样（`/ziwei/handoff`，再跳到新会话；跳不过去时如实提示）。
- 草稿（没发出去的字）按命盘保留在内存里，关面板再开还在。

### 3.5 报告页

- 还没写时：阅读栏显示这张盘的徽记、一句说明（14 个方面，约 3 分钟，写完自动保存在本机，可以下载）和"开始写"；左栏列出将要写的 14 个部分。
- 写的过程中：正文逐段出现在阅读栏里；左栏标出已写完、正在写、还没写的部分；顶上一条状态栏显示"正在写第 N / 14 部分 · 名称"和"停止"。只更新正在写的那一部分，已写完的部分不重排。用户往上翻看时不被拉回底部。顶栏"报告"页签上有一个进行中的小点。
- 写完后：左栏是目录，以正文里的实际标题为准；点哪个滚到哪个，滚动时高亮当前部分。左栏底部有下载报告、复制全文、重新写（需二次确认）。
- 中断后：已写的部分照常可读，状态栏提示写到第几部分，并给"接着写"和"重新写"。
- 选中正文里的一段文字（至少 4 个字）时出现"问这段"，点了打开紫微师并带上这段引用。
- 重新写失败且一个字都没写出来时，恢复原来的报告并提示。
- 读到哪里按命盘记在内存里，离开报告页再回来回到原处。

### 3.6 导出文件

- "下载报告"保存一个自带样式的 HTML 文件，文件名 `人生鲲鹏计划_<称呼>_<yyyymmdd>.html`。品牌名"人生鲲鹏计划"只出现在导出文件里，界面上叫"完整报告"。
- 文件包含：封面（这张盘的浑天仪徽记、标题、称呼、生辰、五行局和命宫主星）、命盘页（基本信息 + 十二宫盘）、目录、正文、落款和免责声明。落款文字沿用 v5。
- 屏幕上跟随系统深浅色，宽窗口下目录固定在左侧。打印时一律用浅色：封面单独一页且铺满，命盘和目录一页，标题不落在页尾，表格行不跨页断开。页面上有"打印 / 存为 PDF"按钮，打印时不出现。
- 文件不依赖任何外部资源：没有外链脚本、样式、字体、图片。
- markdown 的解析口径不变（`##` → 分部，`###` → 小标题，管道表格、引用、列表、分隔线、加粗、`<br>`）。分部标题里的"一、"拆成编号；没有编号的部分（盘前须知、十二字心法）不补编号。

### 3.7 会话与数据

- 面板被切走再回来时，回到原来的视图、命盘、页签、选中的宫和面板开合状态，不重播开场。
- 生成过程中切走面板：请求继续。回来时如果还在写，接着显示进度；如果已经写完，显示完整结果，并且已经存进本机记录。
- 任务在看不到的地方写完（面板被切走，或者当时不在那张盘、那个页面），给一条带「查看」的提示。面板被切走期间这条提示不计时，回到面板后才开始倒数，所以回来时能看到。
- 生成过程中换一张盘：旧盘的请求继续跑完并存到旧盘名下，不会写进新盘。（v5 是中止旧请求；v6 的任务按命盘各自独立，不必中止。）同一时间一张盘只有一个生成任务。
- v5 的 `ziwei-pro.library`、`ziwei-pro.readings.v2`（含 v1 迁移）、`ziwei-pro.lastChart.v1`、`ziwei-pro.form`（含 `formV133` 迁移）、`ziwei-pro.autopen`、`ziwei-pro.showadj` 原样可读，键的含义和结构不变。
- 第一次运行 v6 时做一次只增不改的导入：上次看的那张盘（`lastChart.v1`），以及解读记录里有对话或报告、但不在命盘库里的盘，都加进命盘库（称呼取记录里存的，没有就自动命名）。v5 里没点过"保存"的盘因此不会连同报告一起消失。导入只做一次，条目的格式和 v5 完全一样（`id` 仍是 `lib-<毫秒>`，`input.isLeap`），切回 v5 照常能读。
- "清除本机记录"清掉所有对话和报告记录，以及上次命盘；命盘库不动。
- 旧版遗留的 `ziwei-workbench.apikey` 启动时照旧清理。

### 3.8 宿主与性能

- 加载 `client.js` 时只注册 factory：此时 `window.ZWEngine`、`window.ZWCore` 不存在，Three.js 也没有执行。Three.js 不产生全局变量。
- 顶栏第一个控件是"返回会话"；layout 服务不可用时不渲染，其余功能不受影响。
- 不使用 `position: fixed`；浮层都在 `.zp-root` 内绝对定位；`.zp-root` 保持 `isolation: isolate`。
- macOS 桌面端避让窗口标题带（三个 `--dsh-frame-*` 变量，都带兜底值）。首页的 3D 画布可以铺到标题带下面，可点的控件不行。
- 3D 场景在首页第一次可见时才创建；首页不可见、页面隐藏时不渲染；面板卸载时释放全部 GPU 资源、定时器和监听器。连续挂载卸载 30 次不出现"WebGL 上下文过多"的警告。
- `client.js` 里不出现 `setInterval(`。
- 插件卸载时（`ctx.effect` 的清理）中止所有生成任务、释放 3D 场景、移除样式。

### 3.9 可访问性

- 星球标签、宫格、页签、目录项、格局、三方四正里的宫名都是真正的按钮，可以用键盘到达和触发，焦点可见。
- 浮层（设置、生辰表单、全部命盘、中窄档下的紫微师）有 `role="dialog"`、`aria-modal`、可访问名称和焦点陷阱；Esc 关闭后焦点回到触发它的控件。同一时间只有一个模态浮层。
- 对话区是 `role="log" aria-live="polite"`。
- 每个输入控件都有可访问名称。
- 颜色不是唯一的信息载体：四化有字（禄权科忌），格局吉凶有字。

## 4. 设计决定

### 4.1 模块与文件

界面源码从一个 4413 行的 `src/ui-pro.js` 拆成 `src/ui/` 下的小文件。每个文件都是语法完整的一组顶层声明，`build.mjs` 按文件名顺序拼进同一个 factory 闭包，所以文件之间可以直接引用彼此的名字，不需要 import。

```
src/ui/
  00-head.js        React 别名、引擎、版本号
  10-i18n.js        const DICT = /*__ZIWEI_DICT__*/{};   构建时由 i18n/*.json 生成
  i18n/NN-<块>.json  { "key": ["中文", "English"] }        一个键两种语言写在一起，键天然成对
  20-util.js        小工具；const ZWUI = {}（后面的文件往上挂纯函数）
  21-storage.js     本机存储：命盘库、解读记录、偏好、一次性导入
  22-stream.js      SSE 客户端
```

### 4.4 会话态与后台任务

DSH 切走面板会卸载组件，回来时重新挂载。所以这两类状态放在 factory 闭包的模块级，不放在组件里：

- **会话态** `session`：`view`（home / chart）、`chartId`、`tab`、`stage`（board / report）、`when`（当前查看的日期）、`sel`、`pat`、`pane`、`panelOpen`、`introPlayed`、引导问答的进度、各盘的草稿和阅读位置。组件用 `useState` + `useEffect` 订阅。
- **解读数据** `readings`：按命盘 key 缓存对话和报告，首次访问时从 localStorage 读。
- **任务表** `jobs`：按命盘 key 存正在进行的生成任务（对话或报告）。任务自己持有请求和中止控制器，把增量写进 `readings`，结束时落盘。组件卸载不影响任务；重新挂载后订阅即可看到进度。页面关闭前（`pagehide`）把写了一半的报告按"中断、可接着写"落盘。

SSE 的解析和结束语义沿用 v5 的 `openStream`：只有收到 `done` 才算写完；断连、超时、命中长度上限都保留已写的部分并标成可继续。

### 4.5 3D 场景

`src/sky.js` 由原型的 `sky.js` 移植。面板切走会卸载组件，而场景重建很贵，所以场景由模块自己持有画布，卸载时只是"停放"：

```js
const api = __ziweiBootstrapSky();        // 第一次调用才求值 Three.js 和 sky.js；之后是同一个对象
const sky = api.acquire(hostEl, { day, reducedMotion, playIntro });   // hostEl 是 React 渲染的空容器；画布由场景创建并放进去
// sky.ok === false 表示没有 WebGL（接口齐全、全是空操作），调用方改用静态星图
sky.setPlanets(items)                     // [{ id, star, color, beads, names, ming, today }]，由 ZWUi.planetItem 生成
sky.layers(tagsEl, reticleEl, colEl)      // 标签容器、准星、底部文字列；场景每帧直接改它们的 transform / opacity
sky.focus(id); sky.hover(id); sky.onHover(fn); sky.onPick(fn); sky.onGesture(fn); sky.onLost(fn)
sky.grade(day, instant)                   // 夜空 ↔ 晨光
sky.scrim(cssColor)                       // 底部渐隐用的颜色 = 面板底色的计算值
sky.show(on)                              // 进了命盘就停止渲染
sky.dive(id, color, cb); sky.rise(id, color); sky.birth(id, cb)
api.release(sky)                          // 组件卸载时调用：停表、摘下画布、放掉随尺寸变化的渲染目标；5 分钟没人取回才彻底释放
api.destroy()                             // 插件卸载时调用：立刻彻底释放
```

- 浅色主题用晨光，深色用夜空，监听 `body[data-ds-dark-theme]` 的变化。
- 星球标签是 React 渲染的按钮，场景只负责每帧摆位置（直接写 `style.transform`，React 不给这些节点设 `style`）。
- 调用方要画、页面看得见、画布在视口里，三个条件齐了才渲染。减少动态效果时不是每帧都画：有动静之后画一小会儿，静下来就停。
- 上下文丢失时停止渲染并通过 `onLost` 通知调用方退回静态星图。
- 彻底释放时逐个释放几何体、材质、贴图、渲染目标，移除监听器和观察器，取消动画帧，并调用 `renderer.dispose()` 和 `forceContextLoss()`。释放之后所有接口都是空操作，`dive` / `birth` 仍然回调。
- 成本控制：渲染像素上限 240 万；画布超过 140 万像素时多重采样从 4 倍降到 2 倍；帧率持续偏低时自动降一档分辨率。本机实测（M 系列，2218×1082 的缓冲）60 帧，停放后取回不到 1 毫秒，彻底释放后重建约 30–60 毫秒。

### 4.7 原型到插件的换算规则

- 类名加 `zp-` 前缀；根节点仍是 `.zp-root`。
- 原型的颜色变量换成宿主 token：`--bg` → `bg-base`，`--l1/2/3` → `bg-layer-1/2/3`，`--border` → `border-l1`，`--border-soft` → `border-l2`，`--text` / `-2` / `-3` / `-4` → `label-primary` / `-secondary` / `-tertiary` / `-caption`，`--btn` → `button-primary-fill`，`--btn-text` → `label-primary-inverted`，`--hover` → `interactive-bg-hover`。首页的毛玻璃底和文字光晕用 `color-mix()` 从 `bg-base` 派生。
- `@media (max-width: 720px)` → `.zp-root[data-w="narrow"]`；`@media (max-width: 1180px)` → `.zp-root:not([data-w="wide"])`。容器查询（盘面随容器缩放、左栏按高度收文字）保留。
- 字号、间距、圆角、时长就近取 4.6 的档位。例：12.5 → 12；15 → 14；17 → 18；22 / 23 → 24；10 / 14 的间距 → 8 或 12 / 12 或 16；350–500ms → 180 或 240ms。
- `#app { position: fixed }` 换成 `.zp-root { position: relative; height: 100% }`。
- 原型用 `innerHTML` 拼界面；插件里是 React 组件，列表项用稳定的 `key`（宫格用宫位序号）。
- 只属于原型的东西不搬："原型"开关条、五张示例盘、导出预览浮层、本地拼的示例回答和样稿。

### 4.9 文案

沿用 v5 批 C 的规则：说用户认得的东西，按钮说清点了会发生什么，不喊口号，不用 ✓ ⚠ 这类装饰符号，能删的说明就删。界面上不出现"鲲鹏"。所有可见文字走 `t()`，中英文字典的键一一对应，没有无引用的键。文案以原型为准；原型里标了"原型"字样的句子不搬。

## 5. 测试决定

- **纯函数**（`window.ZWUi`）：v5 已有的断言全部保留。新增：日期和时间解析、时辰换算、时间层级的叫法（今天 / 明天 / 这个月 / 今年 / 这十年…）和前后翻、流月流日的请求拼接、星球数据、速览文字、v5 记录迁移。期望值写成字面量，不在断言里重算一遍。
- **报告**（`window.ZWReport`）：v5 已有的表格、标题、列表、打印分页断言保留。新增：分部和编号、徽记是良构的 SVG 且星点数等于主星数、导出文件含封面 / 命盘 / 目录 / 落款、不含外链、深浅色变量键集合相等。
- **存储与任务**（`window.ZWStore`）：在 vm 里用假的 `fetch` 和内存版 localStorage，验证"没有任何组件挂载时任务仍然写完并落盘""换盘不串""中止后标成可继续"。
- **运限**：引擎的流月、流日以前没有任何用例覆盖。从本机的 iztro 2.6.1 对照环境导出一份黄金用例的参考表（含 2025 年闰六月前后、春节前后、换大限前后），存成 fixture，自检逐项比对。
- **深渲染**：同一个假 React，递归调用函数组件，得到完整的元素树。先改 store 再渲染，比较前后两棵树：选宫之后，只有宫格的 `className` / `aria-pressed` / `tabIndex`、连线、宫位卡和窄档页签那几处不同；时间卡、格局卡、中宫、顶栏完全相同，没有节点增减。切页签之后，时间卡的标题等于页签名，格局卡不变，宫格没有增减。
- **结构**：假 React 浅渲染 `ProApp`，检查"返回会话"按钮和 layout 不可用时的降级；对拼好的 `client.js` 做字符串断言（宿主约定的 CSS、不出现 `setInterval(`、加载时不执行引擎和 Three.js）。
- **界面约定**：`scripts/audit-ui.mjs` 按 4.6 的参数更新后继续作为 `verify/all.mjs` 的一组。
- **自检做不到的**，由人在浏览器里看，并在汇报里写明看了什么：点宫位时节点是否真的没有重建、一屏是否放得下、3D 的观感和帧率、反复挂载卸载是否泄漏、打印分页、真实 DSH 里的表现。

## 6. 不在范围内

- Host 半的任何改动；流月 / 流日进 `ziwei-core.js` 的 `buildRequest`。
- 命盘库的导入导出、云同步、分享。
- 英文界面的文案润色（只保证键齐全、意思对）。
- 用懒加载分片（`require.async`）拆出 3D；现在是拼进同一个文件。
- `package.json` `files` 补界面源码。

## 7. 开放问题

- 真实 DSH 里的 WebGL 表现（帧率、和其他面板共存、窗口隐藏时是否暂停）要 Neo 装上后看。
- 面板每次回来都要重建 3D 场景。如果实测重建超过 300ms，再做"离开后保留一段时间"的优化。
- 命盘很多时（几十张）"全部命盘"是否需要搜索，等有人真的攒到那么多再说。
