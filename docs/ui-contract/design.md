# 界面契约 · 视觉（design.md）

> 本文管**视觉规则**：字号、字重、颜色规则、间距、控件几何、状态、明暗、动效。
> **不含**区域树与栏宽（见 [layout.md](layout.md)）。
> **不含值**：颜色值、尺寸值在 [tokens.md](tokens.md)；本文只给「有几档、每档干什么、边界在哪」。
> 一个例外：为了写清「现状 16 种字号要收到 8 种」，本文的迁移清单必须引用具体数值。**引用仅用于迁移，不是规范值**；规范值在 tokens.md 与目标代码里。

- 实测基线：`src/ui-pro.js`（2026-11-07，2501 行，CSS 段 167–896）
- 机器可读：`scripts/audit-ui.mjs` 的 C2（字阶）/ C3（间距）/ C4（字重）/ C15（对比度）按本文规则记账，当前欠账锁在基线里（见 §11）

## §0 设计哲学（用来判断新情况，不是描述现状）

1. **命理数据要有「数据质感」**：干支、星曜、数字用等宽数字或字距，避免正文式排版。盘面是数据可视化，不是文章。
2. **以纸为底、以墨为字**：低饱和、弱阴影、一层描边；层级靠字号/字重/颜色的三级对比，不靠密集分割线与大阴影。
3. **克制**：一屏一个主行动；一屏最多 3 种卡片类型；强调色只出现在「主行动 + 当前选中」。

检验方法：拿一个规范没覆盖的组件，用这三条推它该长什么样。推不出来说明原则太空。

## §1 颜色（规则）

分五组，各自的自由度为：

| 组 | 用 token | 允许写死 | 说明 |
|---|---|---|---|
| 背景 / 表面 | `bg-base` / `bg-layer-1` / `bg-layer-2` / `bg-layer-3` | ❌ | 层级靠表面色差，不靠阴影 |
| 边框 | `border-l1`（常规）/ `border-l2`（较重，深色下星曜空位） | ❌ | 一档宽度 1px；不用彩色边框 |
| 文字 | `label-primary` / `label-secondary` / `label-tertiary` / `label-caption` / `label-primary-inverted` | ❌ | 四级封顶；禁止第 5 级 |
| 品牌 / 状态 | `brand-primary` / `button-primary-fill` / `button-primary-hover` / `state-*` | ❌ | 品牌一个面积主角；状态只做状态 |
| 内容色（星曜/四化/庙旺/吉凶/金） | 插件自有 `--zp-*` | ✅（白名单见 tokens.md §4.3） | 唯一允许写死的组 |

**边框单独成组的原因**（实测教训）：边框混进「表面」表里就会被实现自行发明层级——本仓库曾经出现 9/10/12/14/16/18 六档圆角与多层描边并存。**边框只有两档、宽度只有 1px**，例外需登记。

**对比度底线**：正文/正文级图标 4.5:1；大字（≥18.66px 或 ≥14px 粗体）3:1；图形/边框 3:1。**品牌填充上的前景必须走 `label-primary-inverted`**，不得写 `#fff`（深色主题下 `#fff` 落在 `#a78bfa` 上是 2.72:1，见 §7）。

**颜色禁止清单**：`#fff` 写死、`#000` 用于遮罩、`rgba(0,0,0,.38)` 遮罩、`rgba(128,128,128,.35)` 滚动条、渐变主按钮 + 白字（深色端不达标）。

### 2.3 盘面数据子阶的边界

- 允许 `clamp` 随容器宽度缩放（`cqw`），但**端点值必须是表内 4 个值**；当前 15 处 `clamp` 的 30 个端点里多数越界（8 / 8.5 / 16.5 等）。
- 每个 CSS 规则可保留「先 px 后 clamp」的双写兜底（旧内核无 `cqw`），但审计只认**后一条**（后写的生效）。
- ⚠ **与 layout.md 的耦合**：盘面最小可读宽 `BOARD_MIN=560` 决定主星字号下限 13.5 是否还放得下。改 `BOARD_MIN` 必须回看本节；改子阶上界必须回看 layout.md §3.3。

## §3 间距

### 3.1 语义档位（4/8 网格，半档只允许 2/6）

| 值 | 语义 | 用在哪 |
|---|---|---|
| 2 | 角标/角标内边 | 四化角标、chip 内边 |
| 4 | label → 输入 | 字段标签下方、图标与文字 |
| 6 | 同组控件 | 分段内部、宫格 gap、工具条 gap |
| 8 | 字段间距 | 表单字段之间、按钮组 |
| 12 | 卡片间距 / 段落 | 卡片之间、区块内分隔 |
| 16 | 卡片内边距 | `.zp-card` 内边、弹层体 |
| 20 | 页面左右内边 | 滚动区横向（`PAGE_PAD_X/2`） |
| 24 | 区块间距 | 大区块之间 |
| 32 / 40 | 页面留白 | 顶部/底部大留白 |

**唯一登记豁免**：`88px`（空态纵向留白，一次性版式值）。其余表外值 = 违规。

### 3.2 现状与迁移清单

**实测**：`padding / margin / gap` 共出现 **25 种**不同 px 值（含 0），其中 4 的倍数只有 8 种；**103 处**取值在语义档位外（audit C3 基线）。口径：按**绝对值**判定，负值只用于贴边出血（`-20px` = 20 档合法，`-14px` 违规）；`88px` 为唯一登记豁免、不计入。内部设计审查底稿的修复前按「padding+gap」测得 22 种，当前按更严的「padding+margin+gap」复测为 25 种，本契约取严口径。

|---|---|---|
| 1 | 8 | 归 2（细描边补偿可豁免，但需逐处确认） |
| 2.5 / 3 / 3.5 | 10 | 归 2 或 4 |
| 5 | 7 | 归 4 或 6 |
| 7 | 1 | 归 6 或 8 |
| 9 | 11 | **归 8**（卡片内行距、输入 padding 的主要来源） |
| 10 | 31 | **归 8 或 12**（顶栏 gap、列表内边） |
| 11 | 4 | 归 12 |
| 13 | 2 | 归 12 |
| 14 | 18 | **归 16**（卡片 padding 的第二来源） |
| 18 | 5 | 归 16 或 24 |
| 22 | 3 | 归 24 |
| 46 | 3 | 归 48（弹层顶部内边；可登记豁免） |

**卡片几何规则**：卡片内边距 16（现 14/16 混用）、卡片间距 12、字段间距 8、label 下 4。改完这四条能消掉一半欠账。

## §5 交互状态阶梯

状态是**五段**，任何可交互元素都要能落进其中一段：

```
rest → hover → pressed → selected → focus → disabled
```

| 态 | 规则 | token |
|---|---|---|
| rest | 底 `bg-layer-1/layer-2`，描边 `border-l1`，字 `label-primary/secondary` | — |
| hover | 底提亮一档 / 表面 +6%；**不改文字颜色** | `interactive-bg-hover` |
| pressed | 再深一档（或 1px 内阴影） | `interactive-bg-active` |
| selected | 品牌描边 1px + 品牌 12% 底；**不加粗边框** | `brand-primary` + color-mix |
| focus-visible | 2px 品牌色 outline，offset 2–3 | `brand-primary` |
| disabled | 55% 透明度 + `cursor:default` + 禁指针；**不用灰色文字替代** | — |

复合态规则：`selected + hover` = 选中底 + hover 提亮，不得把选中态覆盖掉；`focus + selected` 同时可见（ring 与描边并存）。

**必须补 focus-visible 的控件**：`.zp-seg button`（分段）、`.zp-list-item`（命盘列表行）——当前键盘走到会「看不见焦点」。

## §6 状态阶梯（数据侧）

| 状态 | 形态 | 语义要求 |
|---|---|---|
| 空 | 居中次级文案 + 符号（太极）+ 1 个 CTA | CTA 是次按钮时，页头主行动必须是唯一落点 |
| 加载（短） | 就地骨架或 200ms 内完成的 spinner | 骨架走 `bg-skeleton`，不用彩色 spinner |
| 流式 | 打字行 + 字数 + 停止按钮 | `role="log" aria-live="polite"`，流式中 `aria-busy` |
| 错误 | 就地错误条，说明「改哪个字段 / 重试」 | `role="alert"`；不得只写「出错了」 |
| 中断 | 已生成文本保留 + 「继续生成」 | 区分截断/断连/超时 |
| 禁用 | 55% + `title` 说明原因 | 不得用隐藏替代禁用 |
| 空结果（工具页） | 就地一句空文案 | 不得隐藏整个区域 |

## §7 明暗主题底线

1. 两套主题都必须过的对比度：正文 4.5:1、大字 3:1、图形/边框 3:1。
2. 系统色不写覆盖；内容色**每个都要有深色值**（浅 10 / 深 10，键集合相等，audit C15）。
3. **品牌填充上的前景禁止 `#fff`**，用 `label-primary-inverted`。当前深色欠账：`#a78bfa` + `#fff` = **2.72:1**（必需 4.5）。
4. 渐变主按钮：若保留渐变，两端都必须是 token 派生，且**渐变最浅端**也要满足 4.5:1；否则改纯色。
5. 小字（≤11px）在深色下用 `label-caption`/`label-tertiary`，不要靠 opacity 压暗。
6. 内容色深色提亮一档：当前实现是 `.zp-star.major` 统一 `color-mix(... 58%, #fff)`，其余四化/吉凶用深色块直接给值（tokens.md §3）。

## §8 动效

| 场景 | 时长 | 曲线 |
|---|---|---|
| hover / 颜色变化 | 120ms | ease |
| 弹层 pop（设置） | 160ms | cubic-bezier(.22,.61,.36,1) |
| 抽屉 slide | 180ms | 同上 |
| 页面级 / 大区域 | 240ms | ease |
| 遮罩 fade | 140ms | ease-out |

- **禁止**：超过 300ms 的 UI 过渡、`animation` 无限循环（除 loading 指示器）、用动效表达状态唯一含义。
- `prefers-reduced-motion: reduce` 时**全部关闭**（当前已实现 ✅），且关闭后状态仍可辨识。
- 状态色变化必须有 transition；布局属性（width/height/top）不做 transition。

## §9 反模式

| 不要 | 为什么 | 改成 |
|---|---|---|
| 自建品牌色 `--zp-accent` | 深色主题无法跟随，白字 2.72:1 | `--dsw-alias-brand-primary` |
| 品牌底上写 `#fff` | 深色主题不达标 | `label-primary-inverted` |
| 渐变主按钮 + 白字 | 渐变最浅端对比不足 | 纯色 fill |
| 字号 12.5 / 13.5 / 11.5 随手混用 | 无字阶，无法审计 | 只用 §2.1 的 8 个值 |
| 间距 9 / 10 / 11 / 13 / 14 / 18 | 无网格，密度不可控 | 用 §3.1 语义档位 |
| 一屏 5 种卡片类型 | 无主次 | 最多 3 种（layout.md §4） |
| `color alone` 表达吉凶 | 色觉障碍不可读 | 补符号/文字 |
| 禁用态灰字代替 | 语义丢失 | 55% opacity + title 说明 |

## §10 交付前检查单

1. 新颜色是否在 tokens.md 白名单里（或走了 `--dsw-alias-*`）？
2. 新字号/字重是否在 §2.1 表内？
3. 间距是否落在 §3.1 档位（表外即失败）？
4. 控件高度/圆角是否只有 §4.1 的档位？
5. 交互控件是否五态齐全（hover/pressed/selected/focus/disabled）？
6. 深色主题：内容色有没有对应值？填充前景是不是 inverted？
7. 对比度：正文 ≥4.5、大字 ≥3、边框 ≥3？
8. 动效时长是否在 §8 表内、reduced-motion 是否关闭？
9. 状态：空/加载/流式/错误/禁用是否都有且语义正确？
10. `node scripts/audit-ui.mjs` 无新增 FAIL、基线未上涨？
