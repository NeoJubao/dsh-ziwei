# v5 规划：命盘工位（Chart Studio）

日期：2026-11-18
状态：**草案，待拍板；未实施**
基线：`v1.6.0` + `fb5887f`（解读记录按命盘持久化、流式空白气泡修复）
关联评审：2026-11-18 产品/UX 评审、DSH 官方插件口径评审
调研对象：自媒体工作台 `dsh-media-desk` 2.6.1（MIT），本机安装于
`~/.dsh/profiles/desktop/node_modules/dsh-media-desk/`

---

## 0. 一页纸

**v4 为什么失败**：把自媒体工作台的**皮相**（五页导航、300 字重大标题、玻璃顶栏、卡片墙、大量留白）
直接搬到紫微盘面上，盘面从主角变成页面里的一个模块；同时重做了 IA，用户失去了熟悉的看盘路径。

**v5 只借交互骨架，不换视觉皮肤**：
- **工位**：宽屏把「对话」和「盘面/报告」并排放，盘面不再被抽屉遮住。
- **产物**：完整报告是独立产物（进度 → 完成 → 全屏阅读 → 选中改写），不是聊天消息。
- **上下文**：选中宫位或报告段落，成为对话的引用上下文；不是从零打字。
- **反馈**：阶段进度、可取消、可撤销、复制/保存成功才提示。

**实施顺序**：先信任与反馈（不碰布局）→ 报告产物 → 工位并排 → 回访与记录 → 官方上架。
**官方上架前必须解决**：插件描述不说清 AI 解读/入口/数据去向；详情页截图不在发布包；
版本与 `[Unreleased]` 未收口。
**不做什么**：五页 IA、云同步、自动解读、卡片墙、玻璃拟态皮肤、把盘面塞进 Bento。

**待拍板**：① 示例盘用徽标还是清空默认表单；② 宽屏并排是否默认开启；③ 报告放在画布页签还是右侧面板。

## 1. 深度调研：自媒体工作台到底好在哪

调研方法：读其 README、`dist/client.js` 中的组件行为与 CSS、以及本机安装版本的结构；
只记录**交互模式**，不复制 CSS/组件代码；其 MIT 许可证允许参考，但 v5 不引入它的样式资产。

### 1.1 真正值得借的 7 个模式

| # | 交互模式 | 媒体工作台的证据 | 为什么好 | 对紫微的适配 |
|---|---|---|---|---|
| 1 | **工位并排：对话在左，产物在右** | `.md-studio`：`--chat-w: 320px`；`.md-studio-chat` + `.md-sheet`；窄档 `.md-chat-toggle` 把对话收成浮动开关 | 对话和产物同时可见，改稿时不用来回开关；窄屏才退化为抽屉 | 宽屏：对话 320 + 画布（盘面/报告）；窄屏：全屏对话 + 「盘面」切换 |
| 2 | **产物不是消息** | `.md-sheet` / `.md-bento` 的 article、shots 是独立 tile；有 `is-open` 放大态、独立滚动、字数脚注 | 报告/稿件可以反复查看、整体导出；聊天只承载「怎么说」 | 报告独立为画布页签；聊天只留问答；报告可全屏阅读 |
| 3 | **阶段进度卡** | `.md-progress-card`：每步 `is-done` / `is-active`，active 用 shimmer；运行中给「取消」 | 长任务有可感知阶段，不是一条“思考中…”；失败/取消位置明确 | 14 部分报告：当前部分 + 已完成部分 + 字数 + 停止；不再只显示原始流 |
| 4 | **选中文本→让助手改这段** | `.md-pick` 浮动按钮；`chatQuote` + `.md-composer-ctx` 引用条；发消息带上下文 | 把“改哪里”变成可指的动作，避免用户复述长文 | 报告选中段落 → 「让紫微师改这段」→ 引用条；宫位也可作为引用对象 |
| 5 | **完成后的上下文建议** | `.md-suggest`：完成后显示「标题再短一点」「语气轻松一点」等按钮 | 降低下一轮提问成本，尤其适合不知道能问什么的用户 | 报告完成后给「这十年事业」「感情要注意什么」「说得再口语一点」 |
| 6 | **全屏查看器** | `.md-viewer`：遮罩 + 大卡片、左右键切图、下载、让助手改 | 产物需要“认真读”的独立空间，不被窄栏挤压 | 报告全屏阅读：章节导航、导出、复制、选中改写 |
| 7 | **操作回执与撤销** | `md-toast` + `undo`；`H(ops,{undoable})` / `canUndo`；操作有 receipt | 用户敢点删除/改写；失败有明确回执 | 删除命盘、清空对话、覆盖报告：确认 + 撤销/回执 |

补充可借的细节：

- **自动滚动纪律**：文章只在生成中跟随到底，生成完成后回顶部；用户上滚后不强行拉回。
- **输入法保护**：发送前判断 `event.nativeEvent.isComposing`，中文输入 Enter 不误发。
- **容器查询**：按容器宽度而不是 viewport 适配；对话栏窄档折叠，不靠魔法断点。
- **排版对比**：产物用更松的行高/更大的字号，操作界面保持紧凑；不是全屏都放大。
- **操作反馈**：按钮有 busy / disabled / success / error 四态，不“点完没反应”。

### 1.2 不该搬的部分

| 媒体工作台做法 | 为什么不适用 |
|---|---|
| 五页 IA（灵感/内容/排期/复盘/风格） | 紫微的核心任务是“一张盘看深”，不是内容生产流水线；多页会打断看盘 |
| 玻璃拟态顶栏 + 胶囊导航 | 在盘面密集信息旁会抢注意力；v4 已证明观感不适合 |
| 300 字重、大留白 Hero | 盘面本身是主角；大标题会把首屏纵向空间吃掉 |
| 卡片墙 / Bento 拼贴 | 宫格本身就是高密度数据；再叠卡片会变成“卡片里的卡片” |
| 环境光斑、旋转/漂移动效 | 长时间看盘时是噪音；不符合“专业工具”气质 |
| 把报告做成多个卡片 tile | 报告是线性阅读物，不是图片/分镜拼贴 |

**v4 的教训**：参考对象没错，错在**把参考产品的视觉语言当成产品语言**，并且改了 IA。
v5 的边界是：借它的**空间关系、产物生命周期、上下文动作、反馈节奏**；视觉继续用本项目
既有 token、字号密度和盘面布局。

## 2. v5 设计：命盘工位

### 2.1 五条原则

1. **盘是主角**：任何时候都不让对话/报告把盘面完全遮住；宽屏必须能边看边问。
2. **报告是产物**：报告有独立生命周期（空 → 生成中 → 完成 → 阅读 → 再修改），不是聊天记录。
3. **先选再问**：宫位、四化、报告段落都能作为对话上下文，减少重复描述。
4. **状态可恢复**：命盘、解读、报告、上次读到哪，回来还能继续。
5. **视觉不换皮**：沿用当前 token、字号、间距、盘面密度；媒体工作台只提供交互骨架。

### 2.2 结构（宽屏）

```
┌────────────────────────────────────────────────────────────────────┐
│ 紫微斗数 · [命主 / 四柱]            [看盘] [解读]       存 导出 设置 │
├───────────────┬────────────────────────────────────┬───────────────┤
│ 对话           │  画布：  [盘面]  [报告]             │ 当前宫位/信息 │
│ 引导/消息      │                                    │ （可收起）     │
│ ...            │  盘面（12 宫，可点）                │               │
│                │  或 报告（章节/正文）               │               │
│ 引用：命宫 癸丑 │                                    │               │
│ 输入框         │                                    │               │
└───────────────┴────────────────────────────────────┴───────────────┘
```

- 进入「解读」= 进入工位，不是打开遮罩抽屉；左侧栏（生辰/命盘库）收成顶部上下文或可展开浮层。
- 画布两个页签：**盘面**（默认）与**报告**（有报告时出现）。
- 当前宫位/信息列可收；窄档隐藏，改为对话里的引用 chip。
- 视觉上仍是当前的白底/细边/小字号，不引入玻璃、Hero、Bento。

### 2.3 结构（窄屏）

```
[对话] [盘面]   ← 顶部两态
┌──────────────────────────┐
│ 对话（全宽）              │
│ ...                      │
│ 输入框                   │
└──────────────────────────┘
点「盘面」→ 临时看盘；点宫位 → 回到对话并带引用
报告完成 → 全屏阅读层（可返回对话）
```

### 2.4 四个核心交互

**A. 工位模式**
- 顶栏 `看盘 / 解读` 是模式开关，不是五页导航。
- 宽屏点「解读」：左侧栏收起，对话 320 + 画布并排；点「看盘」回到原有布局。
- 窄屏点「解读」：全屏对话；「盘面」按钮临时切回盘面；选宫位后自动回对话并带入引用。
- 记住上次模式（本地偏好），但**不自动发起生成**。

**B. 报告产物**
- 画布「报告」页签：
  - 空：14 部分清单 + 「生成完整报告」。
  - 生成中：阶段进度卡（当前部分 / 已完成 / 字数 / 停止），不是空白气泡。
  - 完成：报告阅读面（目录 + 正文 + 字数 + 全屏/导出/复制）。
- 聊天与报告分开：追问不覆盖报告；报告始终可回到「报告」页签。
- 报告状态持久化：`lastReport` 文本 + 生成时间 + 是否完成 + 命盘 key。

**C. 选中即问**
- 报告正文选中一段 → 浮动「让紫微师改这段」→ 输入框上方引用条 → 发送。
- 盘面选中宫位 → 对话引用 chip「命宫 · 癸丑」；建议动作「解读这个宫位」「这十年」。
- 引用可取消；新问题默认仍针对整张盘，除非有引用。

**D. 阅读与反馈**
- 全屏阅读层：章节导航、字号舒适、键盘 ←/→ 切章节、Esc 关闭；导出/复制固定。
- 生成中可停止；完成/失败有回执；复制成功才显示「已复制」；删除/清空可撤销或二次确认。
- 生成时用户上滚即停止跟随，回到底部再恢复跟随。

### 2.5 视觉边界（防止重蹈 v4）

| 项目 | v5 规则 |
|---|---|
| 字号 | 操作界面继续 11–14px；对话欢迎语最多 20–24px；**不做 34/300 的全屏 Hero** |
| 颜色 | 只用 `--dsw-alias-*`；星曜/四化内容色保留现有明暗两套 |
| 卡片 | 不新增卡片墙；对话、画布、信息列是三个稳定区域，不互相嵌套 |
| 动效 | 只保留 150–250ms 的淡入/滑动；不做光斑、漂移、旋转；尊重 reduced-motion |
| 密度 | 盘面密度不变；报告阅读可松，操作区保持紧 |
| 参考方式 | 只借结构/状态/动作；不复制 `md-*` 类名、CSS、组件代码 |

## 3. 路线图

### Phase 0 — 信任与反馈（1–2 天，不碰布局）

| 任务 | 验收 |
|---|---|
| 示例盘身份：默认生辰/示例 CTA 加「示例盘」徽标 +「换成我的生辰」；不再把示例称为“命主” | 首次进入能分清示例与自己的盘 |
| 解读记录 key 纳入排盘设置（已修 `fb5887f`） | 换月柱/晚子时口径不套旧解读 |
| 复制/保存/同步/删除的诚实反馈：成功才提示；失败可见；删除/清空二次确认 | 各动作失败时用户能看到原因 |
| 中文输入法 Enter 保护；流式上滚不抢滚动 | 中文输入不误发；阅读长报告不被打断 |
| 恢复记录可见：解读按钮显示「· N 轮」或上次时间；设置里加「清除本机记录」 | 用户知道记录存在、可清除 |

**不做**：这一阶段不改任何主布局。

### Phase 1 — 报告产物（2–3 天）

| 任务 | 验收 |
|---|---|
| `lastReport` 状态 + 持久化；预览/导出/复制始终指向报告，而不是最后一条回答 | 追问后仍能导出完整报告 |
| 画布加「报告」页签；空/生成中/完成三态 | 报告不再埋在聊天里 |
| 阶段进度卡（14 部分）+ 停止/继续 | 长任务有阶段感，可取消 |
| 全屏阅读层（章节导航、导出、复制、Esc） | 13k 字报告可舒适阅读 |
| 完成后给 3–4 个上下文建议 | 用户知道下一轮能问什么 |

### Phase 2 — 工位并排（3–5 天，风险最高，先开关）

| 任务 | 验收 |
|---|---|
| 顶栏 `看盘/解读` 模式开关；宽屏并排（对话 320 + 画布） | 盘面不再被抽屉遮住 |
| 窄屏全屏对话 +「盘面」切换；选宫位带回对话引用 | 窄屏也能边看边问 |
| 选中宫位/报告段落 → 引用 chip；建议动作 | 用户不用重复描述上下文 |
| 自动滚动/停止跟随；焦点陷阱；容器宽度适配 | 键盘、读屏、窄屏都不坏 |
| 保留旧抽屉回退开关（设置项） | 不喜欢并排的用户可切回 |

**风险控制**：默认关闭“并排”开关 → 内部使用 1 周 → 默认开启；不做五页、不做 Hero、不换视觉皮肤。

### Phase 3 — 回访与记录（2 天）

- 「最近解读」在命主信息卡/命盘库显示：命主名、时间、轮数、是否有报告。
- 命盘库折叠成一行；最近盘与已保存盘分开，不新增页面。
- 本机数据：清除单张/全部解读、存储占用/上限提示、导出/导入 JSON（可选）。
- 报告与命盘记录同一 key；换设置不串盘。

### Phase 4 — 官方上架（1–2 天）

- **B1 描述**：`locale/zh.json` / `en.json` 的 `meta.description` 补：入口标签
  「左侧栏 → 紫微斗数 Pro → 紫微师解读」；解读会把命盘/生辰文本发给你配置的模型提供方；
  免责声明与限制；插件停用后不发生什么。
- **B2 详情页**：加一张 640×300 的 `meta.detail` 预览图（或把截图打进发布清单），
  更新 README 截图为当前 v1.6/v5 版；删除重复 badge、修 `docs/assets/README.md` 的
  “还没有这些文件”过期说明。
- **B3 发版**：升版本、清 `[Unreleased]`、重跑 `release-pack`、勾 `docs/PUBLISHING.md`
  真机走查；如果 npm 上已有 1.6.0，不能直接重发。
- 建议项：导出 `Config`（diag/超时/预算）、`host-diag.log` 加上限并移到数据目录、
  持久化行为测试（localStorage/report artifact）、移除 `export { handleInterpret }` 的测试洞。

**发布前总验收**：`verify/all` 全绿；真实宿主浅/深/窄/390px 走查；插件详情页中英文；
安装/禁用/卸载；报告导出 HTML；`npm pack` 文件清单无破图/死链。

## 4. 评审结论如何进入规划

| 评审发现 | 进入阶段 |
|---|---|
| 示例盘身份、复制假成功、同步失败不可见、删除不可逆、无盘保存静默 | Phase 0 |
| 恢复不可见、无清除记录、报告导出指向最后回答、报告被追问埋没 | Phase 0 + 1 |
| 左栏重复、mid/narrow 选宫格无反馈、自动滚底、IME Enter | Phase 0 + 2 |
| 官方描述/详情页/发版状态 | Phase 4 |
| 无 Config、diag 日志无上限、持久化行为测试空白 | Phase 4 |
| 云同步/自动解读/五页/卡片墙 | **不做** |

## 5. 待拍板的 3 件事

1. **示例盘**：默认表单清空（更干净，但新用户要多填）还是保留默认 + 徽标（改动小）？
   建议：保留默认 + 徽标 +「换成我的生辰」，并在首次提示。
2. **工位并排**：宽屏是否默认开启？建议先默认关闭开关，内部试用后再默认开。
3. **报告位置**：画布页签（推荐）还是右侧独立面板？画布页签能同时保留聊天和盘面入口。

拍板后再拆实现任务；本文件是规划，不是已实现承诺。
